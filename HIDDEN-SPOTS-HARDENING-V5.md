# UNFINISHED — V5.3 Hidden-Spots Hardening

Date: 2026-09-11
Status: ACTIVE SUBMISSION CONSTRAINTS

## Existing product hidden spots
1. **Causal prior author** — prototype implemented: prior human authors `anchor + vector + reach` by spatial gesture.
2. **Counterfactual authorship** — evidence must preserve `f(A,B) ≠ f(A',B)` and `f(A,B) ≠ f(A,B')`.
3. **Browser fun ≠ Decentraland proof** — browser 2.5D can prove comprehension/interaction, not DCL runtime quality.
4. **Persistence** — transferable URLs/local state/receipts exist; shared durable persistence remains yellow.
5. **Concurrency** — exact local CAS/stale refusal exists; shared atomic CAS remains yellow.
6. **No self-completion** — opaque prototype identity enforces this in normal flow; production requires platform identity.
7. **Identity integrity** — display name is presentation, never authority. No fabricated HUMAN state.
8. **Retention by consequence** — return reason is “what happened after what I left,” not streak/loot/XP.
9. **Gallery drift** — lineage remains capped and secondary to inherit → solve → play → author.
10. **Real Decentraland Mobile** — actual avatar/camera/collision/performance still require DCL validation.

## V5.3 experiment-integrity hidden spots
11. **URL leakage** — fixed for matched cold tests. State is carried in an opaque `s=` token, then hidden behind neutral `?play=<fingerprint>` after load. HUMAN/WORLD/geometry are no longer readable in the tester-facing URL.
12. **Source-priming leakage** — Demo Mode may narrate provenance; Cold-Test Mode uses neutral badge + neutral creator residue before debrief.
13. **Meaningless human residue** — operator HUMAN authoring requires an alphabetic name/alias. `.` / `...` are rejected.
14. **Evidence mix-up** — each run exports runtime `5.3.0-submission`, condition fingerprint, pair/run labels, UI mode and test-safe flag.
15. **Session contamination** — each cold-test should still use a fresh browser/profile/device. Tokenized state reduces URL leakage but does not magically make localStorage multi-user infrastructure.
16. **Device skew** — prioritize real phones for any remaining cold tests because the competition is mobile-first.
17. **Small-N ambiguity** — do not force a PASS from a 3/2 split. If results are ambiguous and time remains, extend tests rather than narrating certainty.
18. **Operator coaching** — after the single instruction, operator remains silent until debrief.

## Submission/design hidden spots
19. **Demo clarity vs test validity** — solved by separate Demo Mode and Cold-Test Mode rather than compromising both.
20. **Visual polish masking weak causality** — V5.3 changes presentation and interaction but keeps the validated causal engine frozen underneath.
21. **Interaction friction** — completion now uses press-and-hold commitment; direct canvas route interaction and D-pad remain available.
22. **Generic AI aesthetic** — the canonical visual system is dusk plum/mulberry/coral/lilac with editorial typography and spatial stone-world cues; generic dark-blue/black AI-dashboard styling is explicitly out.
23. **Reward without consequence** — the emotional peak is route reveal + causal receipt, not arbitrary points/badges.
24. **Submission-time scope explosion** — no full 3D rewrite, no heavy backend, no new game mode before submission.

These move to PDPB/EXECUTION if the concept passes. They must not be falsely marked green from the submission prototype.
